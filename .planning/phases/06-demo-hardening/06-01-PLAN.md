# PLAN 06-01 — Seeded demo case + one-command startup + runbook

## Objective

Make the finale demo bulletproof: a deterministic generator builds the "Operation Ledger" cyber-fraud case (~50 artifacts, 5 sources, including tampered media and a pulse-liveness video), seeded through the real upload pipeline; the Docker Compose stack cold-starts with all models baked into the image (no runtime downloads); and a timed runbook lets a non-technical presenter drive the full narrative — ingest → graph → timeline → findings → summary — in under 5 minutes.

## Wave 2 — expansion

### Task 6.2 — "Operation Ledger" demo-case generator
- **read_first:** `phases/06-demo-hardening/06-CONTEXT.md`, `apps/api/app/services/extraction.py` (source types)
- **action:** Write `apps/api/app/seeds/generate_demo_case.py` (deterministic, seeded RNG) producing ~50 artifacts under `apps/api/seeds/operation-ledger/`: 12 WhatsApp-style chat `.txt` (fraud coordination, shared phone + money-mule names across chats), 10 screenshots (Pillow-rendered chat/banking screens), 8 bank-statement images (one with an edited amount), 12 auth log files (including 3 AM brute-force sessions), 5 pcap summaries, 3 tampered images (edited amount, stripped EXIF, face video with pulsing green channel for FRD-03). Every artifact carries realistic IST timestamps.
- **verify:** Run the generator twice; `diff -r` of outputs is empty (determinism); file count is 50 ± 2.
- **acceptance_criteria:**
  - Generator is deterministic (byte-identical reruns); artifact count and the 5 source types match the spec; the planted evidence (shared phone, edited amount, anomalous logins, pulsing video) is present.

### Task 6.3 — Seed through the real pipeline
- **read_first:** `apps/api/app/main.py` (upload endpoint)
- **action:** Write `apps/api/app/seeds/seed_demo.py` (run via `docker compose exec api python -m app.seeds.seed_demo`): uploads every generated artifact through `POST /api/artifacts` (no direct DB writes), then runs extract → correlate → timeline → analyze → media/pulse/anomaly endpoints in order.
- **verify:** After seeding, `GET /api/findings` is non-empty and includes at least one finding of each type: `shared-identifier-link`, `tampered-media`, `pulse-liveness`, `login-anomaly`.
- **acceptance_criteria:**
  - Seeding exercises only production code paths; all four finding types exist afterward with full provenance.

### Task 6.4 — End-to-end < 5 minute demo verification (DEM-01)
- **read_first:** Task 6.1–6.3 outputs
- **action:** From a clean Compose state, time the full presenter flow: `up` (already running) → seed → open UI → upload one new artifact → graph → timeline → findings → summary (mock Gemini offline path if needed). Record wall-clock time per step.

- **acceptance_criteria:**
