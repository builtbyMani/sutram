# 05-CONTEXT.md — Phase 5: explainability-fraud

**Phase goal:** Ship findings with full provenance, the audit trail, AI case summaries with citations, plus media-tamper signals and log anomaly scoring.

## Locked decisions

- Inherited: schema contract from 01–04 CONTEXT.md. This phase only adds tables.
- **[PROPOSED]** Schema additions: `findings(id INTEGER PK, title TEXT, description TEXT, rule_or_model TEXT, confidence REAL, artifact_ids_json TEXT NOT NULL, snippet TEXT NOT NULL, created_ts TEXT)`; `audit_log(id INTEGER PK, ts TEXT /* UTC ISO */, actor TEXT, action TEXT, detail_json TEXT)` (append-only — no UPDATE/DELETE code paths); `media_signals(id INTEGER PK, artifact_id INTEGER FK UNIQUE, ela_score REAL NULL, ela_heatmap_path TEXT NULL, exif_flags_json TEXT, deepfake_score REAL NULL, deepfake_model TEXT NULL, created_ts TEXT)`; `anomalies(id INTEGER PK, artifact_id INTEGER FK, feature_json TEXT, score REAL, explanation TEXT, created_ts TEXT)`.
- **[PROPOSED]** Findings are generated by deterministic rule functions, each emitting all EXP-01 fields: (a) `shared-identifier-link` from `relations` (confidence = relation confidence), (b) `tampered-media` from `media_signals` flags, (c) `login-anomaly` from `anomalies`. API: `POST /api/v1/analyze` (runs all generators, idempotent rebuild), `GET /api/v1/findings`.
- **[PROPOSED]** NFR-02 hard gate in two layers: (1) API validates `artifact_ids_json` non-empty + `rule_or_model` + `snippet` present before insert (422 otherwise); (2) the web `FindingCard` component renders only when all provenance fields exist, else shows a "provenance missing — suppressed" placeholder.
- **[PROPOSED]** Case summary: `POST /api/v1/case/summary` builds a prompt from findings + artifact metadata, calls **pinned `gemini-3.8-flash`** with an instruction to cite every claim as `[artifact:<id>]`, retries on 429/503 (STACK.md §10), post-process verifies each cited id exists in the DB. Offline/network failure → UI shows a graceful "summary unavailable offline" state; findings still render (STACK.md pitfall #8).
- **[PROPOSED]** ELA: recompress JPEG at quality 90 via Pillow, absolute difference vs original, mean diff → `ela_score` (0–1), heatmap PNG saved under `apps/api/storage/ela/`. EXIF flags: missing/striped EXIF, `DateTimeOriginal` vs file mtime mismatch, `Software` tag indicating an editor.
- **[PROPOSED]** Deepfake: lazy-load `dima806/deepfake_vs_real_image_detection` (or the v2 ONNX variant) on first `POST /api/v1/media/{id}/deepfake` call with a 60 s timeout; on any failure return heuristics-only (`deepfake_score: null`, `deepfake_model: null`). Scores are labeled as model signals, never ground truth (REQUIREMENTS.md FRD-02).
- **[PROPOSED]** Anomaly detection: `scikit-learn==1.9.1` IsolationForest (`contamination=0.1`) over per-session log features `{hour_of_day, failed_attempts, bytes_transferred}`; `anomalies.explanation` names the contributing features (ANO-01).
- **[PROPOSED]** FRD-03 pulse-liveness (rPPG): new module `apps/api/app/services/pulse.py` ports `detrend`, `bandpass`, `estimate_bpm` verbatim from `~/workspace/pulse-detector/pulse_detector.py`; face ROI extraction follows the prototype (mediapipe `FaceMesh` → landmark bounding box → forehead/cheek ROIs as box fractions → green-channel mean per frame). Frame sampling: every 3rd frame (≈10 fps effective); requires ≥ 5 s of face-tracked signal, else `pulse_verdict="insufficient-signal"` and no finding is emitted.
- **[PROPOSED]** FRD-03 schema: `media_signals` gains `pulse_bpm REAL NULL, pulse_snr REAL NULL, pulse_verdict TEXT NULL` with verdict vocabulary `real-face-supported | inconclusive | possibly-synthetic | no-face | insufficient-signal`.
- **[PROPOSED]** FRD-03 calibrated thresholds: SNR ≥ 12 → `real-face-supported`; 6–12 → `inconclusive`; < 6 → `possibly-synthetic`. Confidence = `clip(snr/20, 0.05, 0.95)` for directional verdicts, `0.5` for inconclusive.
- **[PROPOSED]** FRD-03 API: `POST /api/v1/media/{id}/pulse` (video artifacts only); findings-engine rule `pulse-liveness` emits a finding carrying artifact id, method (`rPPG remote photoplethysmography`), SNR, and confidence per NFR-02. The finding description always carries the "supporting signal, not proof" caveat. Deps: `opencv-python`, `mediapipe`, `numpy`, `scipy` (CPU-only).

## Scope fences

- IN: findings engine + API + UI, audit trail UI, cited summaries, ELA + EXIF tamper, deepfake score with fallback, IsolationForest anomalies, fixture verification (tampered image flagged; anomalous logins scored).
- OUT: demo seeding (Phase 6). No finding editing by the investigator; no multi-case support.

## Deferred ideas

- LLM choice beyond Gemini; video deepfake detection; analyst feedback loop on findings.
