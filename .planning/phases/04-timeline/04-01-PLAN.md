# PLAN 04-01 — UTC timeline + artifact detail view

## Objective

Extract event timestamps from all artifact types, normalize them to UTC at ingest (naive timestamps assumed Asia/Kolkata), store them in an `events` table, and ship a unified chronological timeline UI (vis-timeline, one lane per source type) where clicking an event opens the artifact detail page — which this phase also builds as the shared drill-down target for the timeline and the graph.

## Wave 1 — tracer slice (must verify before Wave 2)

### Task 4.1 — Timestamp extraction + UTC normalization + timeline API
- **read_first:** `apps/api/app/models.py`, `apps/api/app/services/extraction.py`, `phases/04-timeline/04-CONTEXT.md`
- **action:**
  1. Add `events(id INTEGER PK, artifact_id INTEGER FK, event_ts_utc TEXT NOT NULL, label TEXT, detail_json TEXT)`.
  2. Create `apps/api/app/services/timeline.py` with `extract_events(artifact) -> list`: chat line timestamps (`[dd/mm/yyyy, hh:mm]`, `yyyy-mm-dd hh:mm:ss`), EXIF `DateTimeOriginal`, leading ISO timestamps on log lines, pcap time-range endpoints. Naive → assume Asia/Kolkata → convert to UTC; explicit offsets honored. No extractable time → no event row (never fabricated).
  3. Wire into the upload flow (runs after extraction); add `GET /api/timeline` returning events ordered by `event_ts_utc` with `{id, event_ts_utc, label, source_type, artifact_id}`.
  4. Fixtures: chat export with 3 timestamped messages (out of order in the file), one EXIF image with `DateTimeOriginal`, one log file with ISO timestamps.
- **verify:** Upload all three fixtures; `GET /api/timeline` returns events strictly ordered by `event_ts_utc`; assert every timestamp ends with `+00:00`/is UTC and the chat messages appear in true chronological order (not file order).
- **acceptance_criteria:**
  - Timeline API returns ≥5 events sorted ascending by UTC timestamp; a python assertion confirms `event_ts_utc` values are all UTC and match the known fixture times converted from IST.

## Wave 2 — expansion
