# PLAN 03-01 — Entity resolution + evidence graph

## Objective

Resolve entities across sources into canonical identities (deterministic merge on shared phone/email/IP, fuzzy merge on PERSON/ORG name similarity ≥ 0.85 via sentence-transformers), build the NetworkX evidence graph with `same_identifier` and `co_occurrence` relations, and render it as an interactive graph in the UI where clicking a node lists every artifact mentioning that identity.

## Wave 1 — tracer slice (must verify before Wave 2)

### Task 3.1 — Correlate engine + graph API (tracer)
- **read_first:** `apps/api/app/models.py`, `apps/api/app/services/extraction.py`, `phases/03-correlation-engine/03-CONTEXT.md`, `.planning/research/STACK.md` (§6)
- **action:**
  1. Add tables `identities(id, kind, canonical_value, merged_entity_ids_json)` and `relations(id, identity_a_id, identity_b_id, relation_type, evidence_json, confidence)`; add `entities.embedding BLOB NULL`.
  2. Create `apps/api/app/services/correlation.py`: `resolve_identities()` — normalize values (lowercase/strip for names; digits-only for phones), deterministic merge on exact PHONE/EMAIL/IP match (confidence 1.0), fuzzy merge on PERSON/ORG via cosine similarity of MiniLM embeddings ≥ 0.85 (confidence = cosine). Canonical value = longest observed mention. Build `same_identifier` relations for identities sharing an identifier and `co_occurrence` for identities whose entities appear in the same artifact.
  3. Add `POST /api/correlate` (idempotent: clears and rebuilds identities/relations) and `GET /api/graph` → `{nodes: [{id, kind, canonical_value, artifact_count}], edges: [{a, b, relation_type, confidence}]}`.
  4. Fixtures: two chat exports — one mentioning "M. Sharma" + phone `98XXXXXX01`, another mentioning "Manish Sharma" + the same phone.
- **verify:** Upload both fixtures, run extraction, `POST /api/correlate`, then `GET /api/graph` shows exactly **one** PERSON identity node whose `merged_entity_ids` has 2 entries; re-running `POST /api/correlate` yields identical node/edge counts (idempotency).
- **acceptance_criteria:**
  - The two name variants resolve to a single identity node (COR-01 proven on the fixture pair).
  - `GET /api/graph` returns valid JSON with `nodes` and `edges` arrays; second correlate run is byte-identical in node/edge counts.
